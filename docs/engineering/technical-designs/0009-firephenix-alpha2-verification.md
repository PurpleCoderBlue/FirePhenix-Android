# FirePhenix alpha.2 修复与发行验证

2026-10-17。本轮接续 [UI 首轮记录](0008-firephenix-ui-checks.md)，目标为修复通知测试、语言与格式检查、动画卡顿及 AI 验收，并安全推送源码、准备长期签名的安装包。

## 已复现及修复

### 通知账号名称

`BaseNotificationDataCreatorTest` 与 `NewMailNotificationManagerTest` 原先共 26 项中有 21 项失败。
本地引入的账号显示名实现提前读取 `email`，在身份未加载或邮箱为空时抛异常；这不是通过填写假邮箱或关闭测试解决的问题。

新增真实 `LegacyAccountDto.displayName` 回归先分别得到 `IndexOutOfBoundsException` 和 `NullPointerException`，再改为安全读取可选的身份邮箱。
自定义昵称和已知提供方名称仍保留，真实邮箱、发送身份和服务器设置没有被改写。
修复后账号模块 8 项及 `legacy:core` 全部 756 项通过。

### Bolt 语言与格式

默认中文环境下，密码可见性和左右滑动无障碍测试共 8 项写死英文断言，实际界面返回中文资源。
测试现在从同一语言资源读取期望值，继续检查实际图标操作和无障碍行为，不更改产品语言或删除断言。
默认中文环境下 Bolt JVM 全部 109 项通过，独立 en/US 测试进程也为 109 项通过。

Bolt 的既有导入顺序和 Markdown 格式按仓库原有 Spotless 规则整理；纯格式改动与功能改动分开提交。

### 重复视图扫描与动画

低开销短时 atrace 在同样 6 次常规设置进入／返回中记录到每帧完整修饰原生视图。
新增计数型真实 ViewGroup 回归先失败，再把完整扫描收敛到布局或外观变化。
普通动画帧仍检查缓存的工具栏／AppBar 背景，避免优化后重新出现滚动页眉变黑。
新控件在布局变化后仍会修饰，关闭时恢复原背景。新增的黑页眉与动态控件回归覆盖这两条约束。

同一组短时跟踪的视图修饰中位耗时为 0.381 → 0.028ms，总耗时为 124.83 → 24.62ms。
同路线设置导航单次帧统计为基线 994 帧、66 慢帧（6.64%），候选包 1273 帧、60 慢帧（4.71%）。
帧数和缓存热度不同，不能把单次比例当成所有页面的确定收益；仍有慢帧，尚不能保证所有长邮件、抽屉及设备满帧。
玻璃采集还增加了完全被视口裁剪的容器剔除：回归先证明不可见子树仍被绘制，再跳过该子树；`clipChildren=false` 的可见溢出内容以像素和绘制次数共同验证，继续保留。
共享动效时长仍为 360ms，未通过缩短动画掩盖卡顿，背景仍独立于内容运动。

ART 方法采样曾使真机设置页发生输入超时；采样已停止并退出无响应进程，账号和设置保留。
后续改用短时 atrace 和帧统计，没有继续长时间方法采样。诊断跟踪标记已从发布源码移除。

### 长总结与 AI 验证

长总结原先逐段串行等待，同轮分段现在共用翻译已有的双请求上限，结果仍按原顺序合并。
回归验证三个独立分段加一次合并：模拟耗时 400 → 300ms，峰值请求数为 2；失败、取消和不完整输出仍不保存半成品。
这一结果是调度回归测试，不是承诺真实服务按同样比例提速。

本轮另获最多 3 次、每次最多 5000 字符的公开固定文本测试授权。未发送任何私人邮件，未购买额度、换服务或自动重试。
使用同签名、无导出业务组件的本地 instrumentation，调用实际 `MailProcessingManager`、已保存的默认千问配置、HTML 处理及加密缓存路径。

|  公开样本   |            输入            |  完成耗时  | 再次读取缓存 |      校验      |
|---------|--------------------------|--------|--------|--------------|
| HTML 翻译 | 20 段正文（3451 字符），另含公开链接文本 | 9055ms | 16ms   | 段落和链接保留、缓存一致 |
| HTML 总结 | 同一公开正文与链接                | 1426ms | 35ms   | 结果成功、缓存一致    |

最初的诊断广播尝试没有取得可用结果，未重试该组；其公开触发方案随后被自动安全审批拦截，已彻底移除。
验证后的 instrumentation 测试包已卸载，固定样本的专用缓存已清除；没有借用私人账户 ID、正文、附件或图片。
这些结果确认所测配置的完整处理路径可用，不代表所有提供商、所有真实邮件或网络条件均已验收。

### 全量检查中新发现的测试环境问题

扩大检查时，IMAP 模拟服务校验漏初始化测试日志依赖，触发 `lateinit property logger has not been initialized`。
按其他协议测试的既有方式补齐每项测试的日志初始化。

本机 DNS 会将非法主机名解析到合成地址，默认代理也会绕开测试自定义的 DNS，导致预期 `UnknownHostException` 的测试实际连到外部网络。
协议测试改用无需 DNS 的非法地址字面量；OkHttp 的 DNS 失败测试使用显式假解析器和该测试专属的 `Proxy.NO_PROXY`。
未修改系统 DNS、代理、真实邮箱服务或产品网络实现。
修复后 IMAP 433、POP3 55、SMTP 99、自动配置 65 项测试报告均为 0 失败。

## 验证命令与边界

执行过完整的：

```bash
./gradlew test lint detekt spotlessCheck --continue --max-workers=2
```

包含离屏采集修复的最终全量运行 `BUILD SUCCESSFUL in 5m 17s`（7410 tasks）。此前失败的日志保留在本机，不覆盖为通过结果。
此外单独运行 Bolt `jvmTest`，相关模块的回归及正式安装包构建。完整运行不等于 `connectedAndroidTest` 或所有提供商的真实服务验收。

真机重复检查了设置导航、导出入口、多邮件会话、中文正文、实际 From 地址及正文滚动；没有发送邮件或触发私人邮件 AI。
已另行确认自动翻译和总结名单为空。原生与 Compose、语言弹窗、自定义色轮、账户子页面的先前检查范围详见首轮记录。

## 发行与隐私

应用编号为 `0.1.0-alpha.2`，内部版本号 35；保持 Thunderbird 24.0 正式版基线，不同步上游开发分支。
新增长期密钥仅保存在忽略的本地 `.signing/` 目录，目录权限 0700、私钥及配置 0600；证书主体仅为 FirePhenix，不含私人姓名或邮箱。

源码上传排除签名密钥、密码、本机配置、构建产物、设备截图、邮件、日志、采样文件和测试探针。
最终复核 8446 个候选源码文件未命中所查的个人邮箱、本机目录及常见凭据特征；提交和 APK 仍需分别检查，模式扫描不构成绝对无泄漏保证。
新提交使用 GitHub noreply 作者地址，保留远端历史，不强推或合入上游 Beta／开发改动。

正式版微软回调需在既有 FirePhenix 注册中增加新包名和证书哈希。后台当前要求重新登录；未宣称已完成服务器登记或正式包 Outlook 登录。
在该验证完成前，不把准备中的安装包冒充可正常登录的公开发行包。签名与回调准备见 [发行说明](../../releasing-firephenix.md)。
