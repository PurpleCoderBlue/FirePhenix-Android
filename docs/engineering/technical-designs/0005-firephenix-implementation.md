## 已确定的行为

### 规则与语言

两个自动总开关初始均关闭，没有对应服务不能开启。保存规则不会打开总开关。仅在打开完整邮件时检查，每个动作按列表顺序执行首条启用且匹配的规则。账户映射中的垃圾文件夹、不完整邮件和超长正文先排除；空条件匹配全部。

源语言使用 Android 系统 TextClassifier 能力，置信度不足或设备不支持时为未知，不为了识别新增在线 SDK。未知语言不满足语言筛选，`en` 可匹配 `en-US`。翻译和总结的手动目标语言分别保存，默认 `zh-Hans`；规则可以各自覆盖。自动处理的实际服务可用性尚未通过真实密钥验收。

### HTML、总结与请求

翻译只更换 HTML 副本的文本节点；模型输出作为文本编码，不能插入模型提供的 HTML。保留原有表格、链接和内联图片关系，沿用原邮件渲染链路；不上传附件或图片。

总结默认排除可识别的 blockquote、Gmail 和 Outlook 引用历史，可显式纳入最近一层作为必要参考；非标准引用结构可能识别不完整。总结先处理全部当前内容，再合并分段结果；最多八轮合并，并检测不能收敛的输出。

自动处理上限为 30,000 个 Unicode 码点，按正文文本统计。手动超限确认一次后连续完成；每段至多 4,000 个码点，每批至多 100 个文本项。参数是保守实现选择，没有宣称已适配所有在线模型的实际限额。

API 错误区分未配置、无效配置、认证、计费、限流、网络、超时、存储和输出异常；截断输出不标成功。不跟随重定向、不隐式重试或切换提供方。每个处理任务持有同一组配置和密钥快照，配置改变后不会把新密钥送到旧地址。

### 存储与账户清理

配置、密钥和结果使用 Android Keystore AES-GCM 与 AtomicFile，保存在 App 私有 no-backup 目录，不进入普通设置导出。缓存文件名使用哈希，按账户、文件夹／邮件、正文、配置版本、模型、语言与相关选项区分，最多保留 100 个缓存文件。

删除服务会删除对应密钥并使结果失效；没有同类服务时关闭相应自动开关。引用已删除服务的规则显示服务缺失，不静默换一家。更改提供方或地址后必须重输密钥。清缓存使用代次保护，旧任务不能在清理后回写。删除账户取消其任务、清理其缓存与专属规则及别名偏好，保留全局服务／规则和其他账户。

### 别名与发信边界

没有接入一个可可靠列出个人 Outlook 完整别名的发现服务，采用需求明确允许的手动方案，界面不把手动保存解释为服务器验证。没有随机生成“已验证别名”，也没有改用 Graph 或扩大 OAuth 权限。

优先级为：当前明确选择、草稿／重发原 From、回复命中的收件别名、唯一已发送历史、账户默认。歧义、已删除的显式地址或原 From 要求先选择，后台推断不能覆盖手动选择。先读本机历史，别名管理页可按需搜索既有服务器已发送文件夹。收藏排序与默认身份分别保存。

撰写页实际 From 可见，仍使用原 MIME、签名和 SMTP 路径。服务器拒绝由原错误流程显示，不换地址重发。本轮没有发送邮件，因此两个真实别名的 From／Sender／Reply-To 及回复路由仍待用户自行验收。

### 玻璃与尺寸限制

Compose 背景单独模糊，文字与图片保持清晰；使用半透明表面、边缘高光和静态背景层次。legacy 使用缓存、降采样的背景场景及共享主题桥接。为避免嵌套页面重复遮盖，页面容器与实际面板分别处理背景层。

没有实现系统级折射、实时采样邮件内容或系统窗口重绘。Android 31 以下的 Compose 模糊使用可读替代，设置页说明限制。没有新增夸张动画。没有完成耗电、长时间帧率或低端设备基准，不把视觉检查当作性能基准。

自动邮件分栏条件为窗口宽度至少 840dp、高度至少 480dp；保留用户已有的明确分栏选项。新安装默认自动；原有“从不分栏”需在常规显示设置改为自动。不能把物理分辨率当作可用窗口宽度。

## 实际设备与界面检查

主要目标为用户已提供的荣耀平板 HONOR CHG-W60，Android API 36，横屏截图 3048×2032、density 400。它不是已核实的荣耀 500 Pro。通过明确序列号的 ADB 操作目标 App 和其安装程序确认，未把投屏宿主点击返回当作安装成功。

最终交付 APK 安装返回 Success，从设备拉取的 base.apk 与交付文件 SHA-256 相同：`0bad04650c3287ccc84226ca3b118e5f6f7bda0901f9f24f83909581c03ca086`。证据为 `checks/honor-final-install.log`、`checks/honor-installed-artifact.json`。最终一次冷启动 am start 记录为 2,208ms，仅是该次观测，不是性能基准。没有使用“卸载安装程序更新”例外，没有修改安装安全检查或通知系统设置。

实际打开过：现有账户／邮件列表、HTML 深色阅读、撰写页 From、别名管理／收藏、原版与玻璃的明暗外观、0／16／32 模糊、服务配置、自动开关与完整规则编辑。空白撰写退出，没有代发邮件。服务真实调用不在这些 UI 检查的结论内。

补充模拟器为本项目创建的 FirePhenix_QA_35，Android 35 AOSP arm64，手机 1080×2400、density 420，可安装并进入真实欢迎页，检查四种外观／明暗组合和横屏滚动。另有 320dp、字体两倍的阅读交互和 1000dp 双栏设置 Robolectric 测试；它们使用 fake 服务，不能作为真实 API 或真机性能证明。

最终 APK 在 API 35 模拟器上仍存在启动缓慢及间歇 ANR，尚未解决。切换到 Apple M1 host GPU 后，冷启动观测为 11,325ms；另一轮未可靠进入目标页；带启动采样的一轮为 13,587ms，随后实际进入欢迎页并读取到 Get started。采样文件为空，未获得可归因的线程证据。日志为 `checks/emulator35-host-samples.json`、`checks/emulator-startup-profile-launch.log`；不能仅凭真机启动较快就断定模拟器问题全由环境造成。Android 36.1 Play 镜像早期出现首次启动 ANR／ADB 响应迟缓，未完成最终版可靠复测，原因亦未确认。

本项目 API 35 AVD 已保存在 `artifacts/firephenix-nightly/emulator/FirePhenix_QA_35.avd`，不打包进源码。现有其他 AVD 未被替换。代表性欢迎页、横屏和真机尺寸检查已完成，但启动可靠性仍是已知问题。分屏、字体和尺寸变化的覆盖范围仅按实际证据报告，不声称穷举所有设备、邮件 HTML 或上游页面。

## 最终修正与复核

- 修复玻璃 Scaffold 半透明容器无法自动匹配 Material 文字颜色的问题，显式使用 Bolt 的 onSurface。新增真实文字布局颜色回归测试：修改前断言失败、修改后通过；日志为 `checks/glass-contrast-regression-before-verified.log` 和最终检查日志。荣耀最终玻璃深色截图中的标签和预览文字可读，像素复核记录为 `checks/honor-glass-night-contrast.json`；这不是 WCAG 或全页面对比度认证。
- legacy 系统栏按实际所需明暗缓存状态，注销观察器；真机新 UI 层级读取恢复正常。实际玻璃浅色系统栏与深色文字、玻璃深色浅色文字均已截图复核。
- 荣耀上用明确标记的假配置完成保存、加密文件检查、强制停止再恢复、规则模型／语言保存与重开。配置名、地址、模型和假密钥均未出现在密文中，随后删除规则与服务。此项是本地 Keystore／界面往返测试，不是真实 API 调用或网络抓包，见 `checks/honor-configuration-roundtrip.json`。
- 在没有服务时尝试打开自动翻译，出现未配置错误，翻译与总结两个自动开关仍为关闭。见 `checks/honor-unconfigured-auto-guard.json`。
- 荣耀实际切换到自动分栏并在重启后观察到邮件列表／阅读双栏，随后恢复原先从不分栏偏好。最终外观恢复原版、跟随系统、模糊 16；没有保留测试服务或启用自动上传。
- 截图索引标记最终版和候选阶段，测试资料不冒充真实服务，隐私裁切／遮盖列于 `screenshots/privacy-transformations.json`。最终玻璃文字修正已用于重新拍摄的荣耀明暗外观截图。

模拟器启动可靠性仍需后续诊断，属于未解决的本地验证问题，并非用户需要提供凭据才能继续的功能。真实服务、SMTP、通知权限与特定机型的阻塞另见上表。代码已实现不等于这些验收项已通过。
