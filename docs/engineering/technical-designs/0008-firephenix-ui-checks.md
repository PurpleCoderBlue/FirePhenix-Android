# FirePhenix：阅读与界面回归记录

记录日期：2026-10-17。需求依据为[最终需求清单第 0 节](0004-firephenix-final-requirements.md)。
本记录区分源码检查、自动测试、真机观察和未验证范围，不代表所有设备、所有页面都已满帧验收。

此文保留首轮 UI 检查的历史结果；通知、语言测试、性能及发行准备的后续结论见[alpha.2 验证记录](0009-firephenix-alpha2-verification.md)。

## 本轮确认的边界

- 远程图片仅按四个精确发件人名单及随应用发布的内置品牌目录判断。手动禁止优先；没有联系人放行，也没有在线目录更新或官方认证标志。
- 旧自动处理规则停用，自动翻译／总结仍需用户主动加入名单；内置品牌不触发自动 AI 处理。
- 当前在一台荣耀 CHG-W60、Android API 36、3048 × 2032 横屏真机检查，没有启动模拟器，没有覆盖系统主题、显示尺寸或代理设置。
- 只进入导出设置页面，不执行实际导出或分享；不发送邮件。本轮没有新增真实 AI 调用，也没有上传私人邮件或诊断素材。
- 应用主题测试后恢复“跟随系统”；未保存自定义颜色、添加别名、改动服务或名单。

## 修复及反馈闭环

### 导出设置退出到首页

进入 Compose 名单页再返回导出设置，可重复触发原生 RenderThread 崩溃。系统退出信息和崩溃堆栈显示 libhwui 的变换递归。
仅增加跨窗口重入保护或跳过 Compose 绘制，仍会复现，不能作为最终修复结论。

最小探针发现新加入的禁用 MaterialButton 尚未登记为玻璃前景时，已被记录进背景源；下一次样式更新后可能形成背景源与玻璃前景的循环。
`GlassBackdropCapture` 改为按按钮、输入框、图标按钮和工具栏的角色提前排除前景，同时处理 Drawable 包装层及跨源重入。
新增控件尚未登记时的回归先失败、修复后通过。

真机在访问名单页和其他设置后，分两轮各进入／返回导出设置 10 次，进程保持不变，未执行导出。
最终包重走设置流程中的 3 次导出入口，并在补查账户 Compose 页面后再重复 3 次，均正常进入和返回。
原始诊断、截图和视频仅保存在本机临时目录；临时源码探针及应用内探针缓存已清除。

### 正文首屏空白

阅读页此前等待 `onPageFinished` 才显示正文，远程资源未完成时可能让已有正文一直隐藏。
阅读专用 WebView 现在在 `onPageCommitVisible` 就显示可用正文，并以完成回调兜底；切换图片状态时保留首屏回调。
旧视图的完成回调不能切换新邮件的容器。

新增首屏回归先失败后通过。打印和签名编辑不启用阅读专用提前显示回调，仍等待完整加载。
真机截图确认中文邮件正文可见，原文翻译按钮隐藏、总结按钮保留，实际发件人地址显示；正文滚动后背景与工具栏不变黑。

### 上下边界切信

切信容器改为竖向；一次手势按起始位置锁定阅读或切信，阅读中途触底不转为切信；横向和多指手势不切信。

真机补测发现内层正文的手势保护还会锁住外层 ScrollView，导致内层到底后外层无法接着滚动。
增加真实嵌套结构的回归，先得到“4 项中 1 项失败”，再把保护位置移到最外层阅读容器的父级，保留正文内部的滚动接力。
完整相关回归修复后通过。

检查脚本最初用可见标题识别当前邮件，标题滚出屏幕会误报切信；核对截图后，改用测试邮件正文的固定特征判断。
真机随后通过：首次手势阅读同一封、横向不切信、到底后另一次上滑切下一封、下一封顶部下拉回上一封。
测试没有点击翻译、总结、回复、发送或名单修改操作。

### 动画、背景及未适配控件

- 原生 Activity 只动画内容子树，排除唯一背景视图。荣耀设备仅设置新版 Activity 转场覆盖仍可能移动整个窗口，补齐待执行窗口转场覆盖后，背景才保持不动。
- 生产应用的 5 处 Compose NavHost 使用 `GlassPageMotion` 的进入、退出、返回进入、返回退出；原生资源与其时长均为 360ms。多邮件会话的 Fragment 入口补齐同组双向资源。
- 常规设置和关于的进出录像抽取 8 个过渡中间帧，在固定背景区域测得相对稳定帧的最佳水平偏移均为 0。此为指定路径的背景验证，不代表所有转场逐帧满帧。
- 原生新弹窗会单独登记滚动条观察；语言列表的滚动条先复现后消失。XML 列表、阅读 WebView 和 HTML 滚动条也隐藏，保留滚动能力。
- 通知操作的可重排条目改为透明玻璃背景；真机截图不再出现整条纯黑矩形。
- Bolt 选择框非玻璃分支改用 Material 默认菜单色，修复无 Bolt 主题环境打开菜单时的 `No ThemeColorScheme provided`，原来的 5 项失败消失。

## 已检查的界面范围

这些是本轮实际进入和返回的场景，不把重复导出计作多个独立页面。

- 设置列表、导出设置、关于、版本新功能、常规设置。
- 显示设置、滚动后的页眉、语言弹窗、外观设置、自定义色轮及取消；分别查看浅色、深色，再恢复跟随系统。
- 互动、翻译与总结设置、发件人名单、自动翻译和自动总结名单切换。
- 通知、通知操作、网络、隐私、调试设置。当前配置没有列出的数据收集入口没有冒充已检查。
- 账户设置及常规、阅读、收取、发送、文件夹、通知、搜索、端到端加密 8 个子页面；账户昵称和颜色弹窗打开后取消。当前头像为图标模式，未为测试切换头像类型。
- 别名单输入框和本地候选下拉菜单；没有添加或删除别名。账户阅读设置未显示旧联系人图片放行选项。
- 多邮件会话列表进入／返回、中文正文进入／滚动／返回、上下边界切信及横向不切信。

账户常规、别名候选、语言弹窗、色轮、深浅主题、通知操作和阅读页均保留了本机截图供核对，不把带有私人数据的图片加入 Git。
最终包另录制了多邮件会话进入／返回，抽取每个方向点击后 0.12、0.23、0.65 秒的帧，确认中间帧有内容位移，已不是瞬间切换。
对固定背景区域使用像素差中位数以降低移动文字遮挡的干扰，4 个过渡样本的最佳水平偏移均为 0。仍未量化该路径的完整实际时长或逐帧耗时。

## 仍未通过或尚未验收

- 根级 `./gradlew test lint detekt spotlessCheck` 已执行，但在 legacy/core 的 756 项测试中有 21 项通知测试失败而终止：BaseNotificationDataCreatorTest 12 项、NewMailNotificationManagerTest 9 项。没有通过干净基线证明其来源，不能宣称根级检查全绿。
- 整个 Bolt 模块的无范围 Spotless 检查还报告未修改 README 的末尾空行及其他源文件的导入顺序问题；没有为了本次 UI 工作批量改动那些文件。
- 设置导航早一轮采样为 1278 帧、64 帧错过截止时间（5.01%，p95 24ms、p99 101ms）；最终包同一路径采样为 1269 帧、62 帧错过截止时间（4.89%，p95 25ms、p99 89ms）。仍有慢帧；样本包含冷启动子页面，不能宣称满帧，也不把两次差异当作受控性能提升比例。
- 没有另一台实体手机、窄屏／分屏、字体放大及全部启动器的完整验收。布局测试不能替代这些真机检查。整套 connectedAndroidTest 未运行，本轮没有独立测试账户或空设备，使用上述受限真机 UI 路径检查现有账户。
- OAuth、外部系统窗口、所有错误／权限分支、完整账户创建、实际导出分享、收件端别名路由及真实 AI 邮件处理没有在本轮重复执行。
- 没有逐一测量所有页面、所有弹窗及所有长邮件的进出帧耗时；仍需继续性能和覆盖检查，不能把以上代表性场景写成全量完成。
