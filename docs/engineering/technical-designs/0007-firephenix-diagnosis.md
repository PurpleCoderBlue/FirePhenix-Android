# FirePhenix：连接、动画与玻璃状态诊断

日期：2026-10-15；2026-10-16 追加回复弹层和动画残留诊断。本文记录真实检查和验证边界，当前候选包与安装哈希以 `artifacts/firephenix-liquid-glass/delivery-manifest.json` 为准。

## 范围变更与保留项

用户后续明确要求仅保留液态玻璃，取代早期两种外观要求。已移除外观模式选择、对应运行分支、两个启停式启动器别名及原版品牌图标，保留共享原生页面、邮件业务与数据。固定 MainActivity 启动入口和玻璃图标避免切换启动组件导致任务退出。

外观只保留玻璃模糊与背景模糊两种滑块；背景图片、主题色、系统／浅色／深色仍保留。拖动值与外部持久化值分开，释放时保存最终值；旧偏好回传不能覆盖尚未提交的拖动值。清除额外内容模糊、透明度及其重复图片处理。

## 选中页眉黑底：可复现、已修正

实际真机截图确认选中行已半透明而上下文操作栏仍为黑底。原因是 AppCompat 的 ActionBarContextView 位于窗口装饰层，在 android.R.id.content 之外；只遍历内容树无法覆盖它。

新增实际 ActionBarContextView 与内容根互为兄弟的回归：旧遍历失败，新窗口遍历通过；重新被框架置黑时也会恢复玻璃背景。只遍历内容外的操作栏容器，不修改其他窗口或系统 UI。荣耀真机再次选中一封邮件，顶部“1 已选择”已显示玻璃材质，截图保存在交付截图目录。

## 千问：连接成功不等于邮件推理完成

- 用户指定地址保持 `https://maas.qianwenaiapi.com/compatible-mode/v1`，模型保持设备已保存的配置；密钥始终在设备内部解密使用，没有导出到电脑。
- 用户发起的旧邮件翻译曾在等待约 120 秒后发生 SocketTimeoutException；新日志又复现 HTTP 200 后持续等待，最终在 180 秒总超时处结束。
- 使用原加密凭据执行模型元数据 GET，真实 HTTP 200。设备 shell 的 DNS 出现 fake-IP 范围，但同样完成 TLS 并返回 401；没有依据把 Clash/DNS 判成根因，也没有更改代理或系统网络设置。
- 经用户授权，代理只执行了一次 `Hello.` 翻译和一次固定短例总结；真实 HTTP 200，分别约 4120ms 和 2838ms，完成严格输出校验。这只能证明这两个短例，不是整封邮件性能验收。
- SSE 合并最终 content，忽略 reasoning_content；缺完成标记、截断、条数不符均失败，不缓存半成品。不自动重试推理请求。
- 官方文档确认用户使用的 qwen3.8-flash 默认开启思考。新增协议回归先失败，再加入混合模型默认 `enable_thinking:false` 后通过；显式用户参数保留优先级，不向未知或仅推理模型注入该参数。没有更换端点或模型。
- 新安全日志区分 request、HTTP response、stream-start、reasoning-first、answer-first、complete／failure，不记录提示词、正文、输出、URL、密钥或推理内容。
- 另一次约 1000 字符公开示例翻译已获用户授权一次；同一确认重复到达只计一次。实际执行 1116 字符公开固定文本，HTTP 200，464ms 首个译文内容、3072ms 完成，无 reasoning-first 阶段；没有重试或发送邮件内容。三次授权测试均已用完，不能再自行调用。记录见 checks/ai-1116-character-device.log。

固定测试入口与阅读输入完全分离。保存配置只做本地校验和加密写入；“检测连接”只 GET 元数据；“测试模型”明确提示会消耗现有 API 额度。

依据：[千问思考模式](https://platform.qianwenai.com/docs/developer-guides/text-generation/thinking)、[OpenAI 兼容协议](https://platform.qianwenai.com/docs/api-reference/toolkitframework/openai-compatible/overview)、交付目录 `checks/ai-fixed-text-device.log`。

## 邮件性能：仍有慢帧，不作完成声明

按 diagnosing-bugs 技能建立真机采样和可返回失败状态的分析脚本。只有实际捕获三进三退、方向与次数匹配，才接受为完整样本；找不到目标邮件、用户导航改变和不完整采样不计为通过。Android uptimeMillis 与包含休眠的 /proc/uptime 不混用。

已保留的改动：仅 RESUMED 的可见 ViewPager 邮件开始正文加载；相同处理 HTML 不重复创建 WebView；隐藏的附件和操作面板不创建完整主题；HTML 预处理在后台并取消过期结果。正文呈现等待页面切换完成，六次采样的动画区间内正文创建次数均为零。

尝试把整个邮件页根布局延迟到 onResume 创建，实际掉帧由 6/644 增至 14/680，已撤销该探针，未把它作为最终优化。

同一封已缓存英文 HTML 邮件的三次进退对比：

|         指标         |  整页透明度动画 |    仅位移动画 |
|--------------------|---------:|---------:|
| 完整切换数              |        6 |        6 |
| 过渡相交的 >=32ms 帧数    |       13 |        6 |
| 过渡最大帧              |    214ms |     75ms |
| 全样本 p99            |    105ms |     61ms |
| 全样本 janky / frames | 15 / 599 | 16 / 630 |

这是一次受设备温度、预热及后台工作影响的样本，不代表所有长邮件的因果基准；整体掉帧率没有改善到可宣布解决。移除整页 AlphaAnimation 可减少离屏合成，进退位移由原来的 12%／4% 改为镜像对称 12% 的候选方案，但该位移方案后来暴露透明页面叠字，已由下文的相邻整页滑动取代。Compose 与原生页均不保留旧 700ms 外观分支。弹窗仍有适合小表面的缩放淡入，不与整页透明度混用。

[Android 硬件加速文档](https://developer.android.com/develop/ui/views/graphics/hardware-accel)说明半透明 View 的离屏合成成本。上游 [Thunderbird PR #11149](https://github.com/thunderbird/thunderbird-android/pull/11149)记录长 WebView 硬件纹理越界问题，因此未重新开启长正文的持久硬件层。[Kyant #104](https://github.com/Kyant0/AndroidLiquidGlass/issues/104)是共享背景的开放建议，不能当成已合并修复；本项目已共享原生采样，不替换指定库。

## 侧边栏时长

原 DrawerLayout 程序打开和关闭六次实测为 431、429、431、421、431、424ms，与页面 220ms 不一致。将程序开关、返回关闭及点遮罩关闭接到相同资源时长；手动拖动继续遵循手势，打断动画取消旧完成回调，关闭完成前不提前触发文件夹切换。该修正的六次真机程序开关耗时为 231、229、231、236、231、229ms（checks/drawer-after.json）；该数字只证明时长，不单独证明没有视觉残留。

## 2026-10-16：透明页叠字与回复黑块

### 页面残留

真机录屏复现设置→常规设置→显示及返回时，新旧菜单同时出现在同一背景上。实际 XML 动画回归在旧代码失败：1000px 页面仅相隔 120px，透明页面覆盖范围重叠。进退四个方向改为 100% 相邻滑动；Compose 同步相同位移、220ms 和缓动，不添加整页透明度合成。该回归修正后通过；真机视觉与帧时长最终结果另列检查记录。

### 回复选择弹层

真机对同一封缓存邮件点回复，出现与用户截图相同的顶部黑矩形；前台仍为 MessageHomeActivity，新增 APPLICATION 类型弹层窗口，自动化层级只有关闭工作表、没有回复选项。这不是已经进入编辑器的证据。

建立零高度调用容器下的实际 Bolt ModalBottomSheet 回归，assertIsDisplayed(Reply) 在原实现失败。仅移除弹层外层 liquidGlass 修饰符时通过，说明异常与该修饰符挂载位置相关；不据此推断所有内部绘制机制。最终将光学绘制移入弹层窗口自身内容容器，使用窗口内坐标和独立场景，保留玻璃材质与既有 Material 手势/定位；零高度调用和现有 AlertDialog 用例通过。额外检查选择回复后关闭状态：原 ViewModel 保留打开状态，回归先失败，再补选择后关闭。

上游 [Backdrop 文档](https://kyant.gitbook.io/backdrop/api/backdrops)说明 LayerBackdrop 依赖布局坐标；[#91](https://github.com/Kyant0/AndroidLiquidGlass/issues/91)记录跨窗口采样位置问题，仍为开放报告，不当作本问题已获上游修复的依据。实际定位依据为本地可重复测试和真机画面。

### 每帧样式查询开销

仅对本 App 调试进程执行方法采样，未采集参数或正文。样本中 GlassViewStyler.resourceName 包含约 36.6ms 采样 CPU，Throwable.nativeFillInStackTrace 约 20.8ms；采样会扰动耗时，不作为 FPS 基准。回归复现每帧遍历无 ID 控件也反复查询资源名（3 次遍历产生 6 次无效查询）。修正为跳过 NO_ID/0，并按 Resources 实例与 ID 缓存名称；ID 改变仍会重新解析。回归验证无效 ID 零查询、不变 ID 仅一次查询。未改变邮件数据、主题持久化和网络行为。

## 外部验证边界

不代发邮件，因此多别名 SMTP From／Reply-To 和回复路由没有真实发信验收。Outlook 联系人适配器未接通，未增加 Contacts.Read；自动远程图片当前只可依已启用的精确发件人规则允许，联系人条件安全地视为未命中。未新增权限、购买额度、启动模拟器、推送代码、发布或部署。荣耀 logcat 不可读时使用本 App 有界私有调试日志，没有修改系统安全设置。

扩大 Bolt 组件检查共 109 例，其中 5 例下拉选择控件用例报 No ThemeColorScheme provided；本次不改该控件样式绕过失败，单独保留失败日志 reply-expanded-tests-before.log。自动审批拒绝改其非玻璃默认颜色的操作，实际未执行；相关回复弹层、原有对话框、阅读状态与导航测试单独列出。
